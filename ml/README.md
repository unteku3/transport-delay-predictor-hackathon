# ML — итоговая Optuna-модель

Одна используемая модель: CatBoost, 69 числовых признаков, файл
`models/optuna_features_v2/model.cbm`. Контракт, хеш и протокол лежат рядом.
Формула: `cur_dev_s + 0.75 × (CatBoost(X) − cur_dev_s)`.
Параметры и веса не меняются при сборке или запуске.

- `service/` — независимый FastAPI-инференс и HTTP-контракты.
- `features.py`, `context.py` — история доступной телеметрии и планового контекста.
- `search_features.py` — зафиксированное расширение до 69 признаков.
- `queries.py` — проверка разрешённых входов без чтения целевых ответов.

API: `GET /health`, `GET /model/info`, `POST /predict`; `POST /train` возвращает 501.
Из корня: `docker compose up --build -d ml`. ML доступен внутри Compose на порту 8001.
[OpenAPI](../docs/api/ml.json) · [Воспроизведение submission](../submission/README.md).

Вложенная групповая development-проверка: MAE 76.23 с на 1141 задании без метки
предполагаемой копии. Это один изученный день; результат не является score платформы
или независимой online-валидацией. Вероятности и индивидуальные интервалы не калиброваны.

Обучение не является частью runtime: для запуска используются включённые фиксированные веса.
