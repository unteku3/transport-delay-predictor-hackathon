# Каталог флагов и решений

Все флаги качества экспортируются всегда. Исходные поля не изменяются; отсутствующее
clean-значение — пустая ячейка, не ноль. Дополнительные фильтры включаются явно
через config.json или параметры clean_csv.py. Флаг сам по себе не доказывает ошибку.

| Флаг | Проверяемое условие | Поля и действие | Параметры и основание |
|---|---|---|---|
| invalid_time | Не парсится event или receive | Без измерений; валидный receive остаётся сообщением | Обязательная доступность времени |
| invalid_key | Пустой tr_id либо строка nan/None | Пакет только в аудит, без состояния | tr_id — ключ ТС по README |
| clock_inconsistent | receive < event | Измерение отложено до event; времена не сдвигаются | Обязательная причинность |
| pending_overflow | На ТС уже 128 будущих пакетов | Новое ожидающее измерение отвергнуто | Инженерный предел памяти |
| exact_duplicate | Совпадает весь сырой payload кроме receive с сохранённым fingerprint | Только last_received, без повторного веса в окнах | Кеш 1024, точная идентичность |
| packet_id_conflict | В кеше тот же unit_id+packet_id с другим payload | Всё измерение отвергнуто | Первый пакет выигрывает, кеш 1024 |
| event_conflict | То же event_time с иными lon/lat/speed/heading/valid | Флаг; далее первый принятый источник по полю | Кеш 1024, причинная политика |
| late | event < наибольшего доступного event этого ТС | Без позиции, скорости, курса и backfill; доставка/качество учитываются | Обязательный общий вариант |
| position_invalid | location_valid не True/1 | lon_clean, lat_clean отсутствуют; speed независимо | NDTP extraDopBit7, README |
| position_missing | Не хватает конечного lon или lat | Нет геоизмерения | Схема, finite-проверка |
| coordinate_range | Конечная координата вне lon [-180,180], lat [-90,90] | Нет геоизмерения | Глобальный допустимый диапазон |
| zero_coordinates | lon=0 и lat=0 | Только флаг; координата не отвергается автоматически | Контекстная диагностика; (0,0) глобально допустима |
| outside_moscow | Координата вне lon [36,39], lat [54,57] | Только флаг | Широкая диагностическая рамка, не граница истинности |
| altitude_suspect | Конечная alt вне [-500,3000] м | Только флаг, высота не корректируется | Грубый городской ориентир, без коррекции |
| speed_invalid | speed отсутствует, не конечна или <0 | Нет принятой скорости; координаты независимы | Скорость движения неотрицательна |
| high_speed | speed >115 км/ч | Только флаг | max(110, округлённый вверх q99.9 раннего train); не доказательство ошибки |
| speed_disagreement | abs(speed − GPS multi-chord average)>40 км/ч | Только флаг | q99 раннего train при обеих скоростях <=80, floor 40 |
| speed_excluded | high_speed И speed_disagreement, включён filter_speed | speed_clean отсутствует, координаты независимы | Только сочетание свидетельств; дополнительный фильтр |
| gps_jump | От последней принятой позиции расстояние >100 м +130 км/ч × dt | Флаг, без автоматического отказа при выключенном quarantine_gps | Консервативный кандидат, запас GPS 100 м |
| gps_quarantined | gps_jump, gap<300 с, нет оснований восстановления, quarantine_gps=True | Текущая позиция кандидат, состояние хранит прежнюю позицию и её возраст | Дополнительный фильтр; скорость отдельна |
| candidate_return | После кандидата пришла достижимая относительно старого состояния точка | Кандидат удалён, принимается только новое измерение | Никакой переписи прошлого |
| candidate_recovery | >=3 согласованных кандидата, span>=30 с, прогресс>=30 м, speed в [1,130], abs(speed−net/span)<=40 | Принимается текущая новая позиция, прежние кандидаты не заполняют историю | Эвристическая повторная привязка, не доказательство истины |
| gap_recovery | Новая допустимая позиция через >=300 с от последней принятой, quarantine_gps=True | Принять текущую, сбросить GPS-историю/кандидаты | Защита от вечной блокировки после неверного якоря |
| recovery_uncertain | candidate_recovery или gap_recovery | Флаг неопределённости, сохраняется в экспорте | Независимой проверки правильности нет |
| same_event_position_ignored | На это event_time позиция уже принята | Не принимать вторую позицию, скорость может заполниться | Первый принятый источник |
| same_event_speed_ignored | На это event_time скорость уже принята | Не принимать вторую скорость, позиция может заполниться | Первый принятый источник |
| heading_missing | Курс отсутствует или не конечен | heading_clean отсутствует | Схема |
| heading_normalized | Конечный курс вне [0,360) | Модуль 360 при надёжной скорости | Представление угла; angular_difference циклический |
| heading_low_speed | Нет принятой скорости или speed<5 км/ч | Нет нового надёжного курса; старый максимум 60 с | Инженерный ориентир, одинаковый во всех вариантах |
| stationary | Причинный автомат в состоянии стоянки | Добавляется флаг, координаты не сглаживаются | Окно 60 с, >=4 наблюдения, span>=45 с, gap<=30 с, median speed<=1, max<=3; detect_stops дополнительно радиус15 м и прогресс<=6 м |
| movement_start | Был stationary, сработало условие выхода | Обнулить длительность распознанной стоянки | speed>=5; при detect_stops расстояние от якоря>20 м либо прогресс>8 м за >=45 с; после провала плотности состояние также сбрасывается |

GPS-средняя требует >=2 предыдущих принятых точек, суммарный интервал 30–120 с и отсутствие
скачка текущего конца. Сумма хорд недооценивает извилистый путь; мгновенная скорость не равна
средней и датчики не независимы. Флаг не доказывает неисправность. История уже ошибочно принятых
позиций также способна испортить сравнение. Эти ограничения сохраняются и у более строгого режима.

При late/duplicate/id-conflict обработчик прекращает разбор полей: отсутствие остальных
флагов у такого пакета не доказывает качество его координат. Отдельный сырой аудит оценивает
масштаб повторов. Экспорт содержит `reasons` (отсортированные коды через `|`) и все логические
колонки, поэтому новое правило не нужно восстанавливать по неявному пропуску.

В расписании отдельно: `flag_geom_invalid` — WKT не finite POINT в диапазоне;
`flag_plan_time_invalid` — время не парсится; `flag_event_id_duplicate` — неоднозначный ID
события; `flag_plan_time_equal` — одинаковый план у одного ТС. Равное время и одинаковая
геометрия сохраняются. `manual_fill` сохраняется. Проверка расписания не восстанавливает фактические прибытия.
