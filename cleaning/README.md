# Причинная очистка транспортной телеметрии

Интерфейс: `Packet.from_row`, `Cleaner.ingest`, `Cleaner.advance`, `snapshot`.
Обработчик не читает расписания, ответы или модели и не делает сетевых запросов.

```python
import json
from pathlib import Path
from cleaning.types import Packet, Config
from cleaning.telemetry import Cleaner
from cleaning.replay import snapshot

config = Config(**json.loads(Path('cleaning/config.json').read_text()))
cleaner = Cleaner(config)
# row — раскодированная строка; T_seconds — время снимка в шкале CSV.
decisions = cleaner.ingest(Packet.from_row(row, seq=0))
decisions += cleaner.advance(T_seconds)
current = snapshot(cleaner, str(row['tr_id']), T_seconds)
```

`seq` задаёт порядок поступления при одинаковом receive_time; для CSV это номер исходной
строки. Перед снимком на T нужно передать все сообщения, полученные к T, и вызвать
`advance(T)`. Полученные после T измерения недоступны, даже если их event_time раньше T.
При receive < event сообщение известно сразу, но измерение ждёт event. Откат времени
запрещён. CSV-время — naive; для Unix-времени NDTP нужен явный адаптер временной шкалы.

`Decision` содержит только новые принятые поля текущего пакета. Плохая позиция не удаляет
допустимую скорость. Старые значения остаются в состоянии с отдельными временами.
`snapshot` возвращает текущие координаты, скорость, курс, давность, доступность и состояние
стоянки. Просроченные измерения становятся NaN: TTL позиции/скорости/курса — 300/120/60 с.
Прежние решения и снимки не пересчитываются. Нет интерполяции из будущего и backfill.

Повтор payload, кроме времени получения, обновляет только доставку. Конфликт
`unit_id + packet_id` отвергается. При равном event_time выигрывает первое принятое
измерение каждого поля; позже можно заполнить только пропуск. Измерение старее watermark
не меняет измерения и их окна. Поэтому часть полезных поздних точек может быть потеряна.

`cleaning/config.json` содержит сохранённые пороги: high_speed=115 км/ч,
discrepancy=40 км/ч. Они получены по ранней реальной телеметрии до 11:30 2026-01-06,
см. `reports/early_audit.json` в закрытом архиве разработки. Голый `Config()` использует discrepancy=60.
Флаги качества экспортируются всегда; отдельного переключателя `flags` больше нет.

Дополнительные `filter_speed`, `quarantine_gps`, `detect_stops` по умолчанию выключены.
Первый исключает скорость только при сочетании высокой скорости и расхождения с GPS;
второй помещает недостижимую позицию в карантин с причинным восстановлением;
третий добавляет пространственную компактность к базовому распознаванию стоянки.
Повтор удалённой неподвижной точки не подтверждает её правильность. Восстановление после
разрыва помечается неопределённым. Тишина не считается стоянкой; длительность считается
с распознавания. Подробные условия и риски — в [FLAGS.md](FLAGS.md).

`read_packets` сохраняет исходные строки, включая большие `packet_id`, и сортирует по
receive_time/seq. `decisions` в конце освобождает очередь будущих измерений для полного
экспорта: этот окончательный аудит нельзя использовать как снимок прошлого времени.
Экспорт raw+clean не удаляет строки и не изменяет исходные поля.

Память ограничена на ТС: пять окон по 512, три кеша по 1024, 128 ожидающих пакетов,
8 GPS-кандидатов. Общего лимита парка/эвикции нет. Offline-сортировка O(N log N),
загрузка O(N) памяти; `advance` обходит известные ТС. Промышленный сервер и восстановление
его состояния после перезапуска не реализованы.

Команды экспорта и проверки приведены в [корневом README](../README.md).
`scripts/diagnose_cleaning.py` обновляет примеры реальных трасс и искусственный пример
задержки EWMA. Это диагностика согласованности, а не истинная разметка ошибок GPS.
